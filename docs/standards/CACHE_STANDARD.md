# Cache Standard — sohamyoga Platform

> **Version:** 2.0.0

## Cache Layer Architecture

```
Request
  │
  ├── L1: In-Memory (Next.js / FastAPI process)
  │     - Ollama response cache (SHA256 keyed, permanent until restart)
  │     - PLATFORM_REGISTRY TypeScript const (build-time static)
  │     - Rate limit counters (Map<ip, {count, reset}>)
  │
  ├── L2: PostgreSQL Materialized Tables
  │     - platform_rate_limit_snapshot (hourly snapshots)
  │     - platform_health_check (5-min snapshots)
  │     - quality_benchmark (weekly computed scores)
  │
  └── L3: Application-level (fetch cache)
        - Admin data: cache: 'no-store' (always fresh)
        - Public platform list: revalidate: 3600 (1h)
        - Static docs: revalidate: 86400 (24h)
```

## Ollama Response Cache (FastAPI)

```python
# ai-orchestrator-platform/backend/app/main.py
# SHA256 keyed cache — same provider+model+prompt always returns cached response

CACHE: dict[str, str] = {}  # In-memory, never persisted

def cache_key(provider: str, model: str, prompt: str) -> str:
    return hashlib.sha256(f"{provider}\x00{model}\x00{prompt}".encode()).hexdigest()

# Cache hit: ~0ms vs. Ollama call: ~1-15s
# Cache invalidation: POST /cache/clear (manual only)
# Cache miss rate target: < 30% for repeated workflows
```

## Next.js Fetch Cache Rules

```typescript
// RULE CACHE-1: Admin real-time data → never cache
fetch('/api/admin/platform-monitoring', { cache: 'no-store' })

// RULE CACHE-2: Admin reference data (36 platforms) → short cache
fetch('/api/admin/ref/platforms', { next: { revalidate: 300 } }) // 5 min

// RULE CACHE-3: Public content (blog, survey embed) → longer cache
fetch('/api/public/blog', { next: { revalidate: 3600 } }) // 1 hour

// RULE CACHE-4: Static metadata (platform configs) → build-time
// Use TypeScript const from @sohamyoga/shared-social-platforms — no fetch needed
import { PLATFORM_REGISTRY } from '@sohamyoga/shared-social-platforms';
```

## PostgreSQL Materialized Cache Tables

These tables ARE the cache — jobs write to them, UIs read from them:

| Table | Written by | Read by | Retention |
|-------|-----------|---------|-----------|
| `platform_health_check` | `PlatformHealthCheckJob` (5min) | Monitoring Hub | 7 days |
| `platform_rate_limit_snapshot` | `RateLimitSnapshotJob` (hourly) | Rate Limit gauges | 7 days |
| `quality_benchmark` | `QualityBenchmarkJob` (weekly) | System Architecture page | Forever |
| `ai_model_performance` | `AIGovernanceAuditJob` (daily) | AI Governance page | Forever |
| `social_platform_analytics` | `SocialAnalyticsSyncJob` (6h) | Social Intelligence | 90 days |

## Cache Invalidation Rules

```typescript
// Manual invalidation endpoints
POST /api/admin/platform-monitoring/health → re-runs health check for all platforms
POST /api/admin/vector-store/embed → re-embeds all content for a namespace
POST /cache/clear → (FastAPI) clears Ollama response cache

// Automatic invalidation
// platform_health_check: rows older than 7 days deleted by ApiLogCleanupJob (daily 3am)
// platform_api_log: rows older than 30 days deleted by ApiLogCleanupJob
// vector_store: re-embedded daily by VectorEmbeddingUpdateJob
```

## Session Cache

```typescript
// Session data: cookie-based (HttpOnly, Secure, SameSite=Strict)
// No server-side session store — stateless JWT-style
// Session expiry: 24h idle, 7d absolute
// Bot sessions: session_token in bot_session table, expires after 24h inactivity

// Do NOT store session data in Redis or in-memory without persistence strategy
// Do NOT rely on in-memory session across process restarts
```
