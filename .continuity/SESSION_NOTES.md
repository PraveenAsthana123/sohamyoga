## Key Decisions
- Voice/typed spatial commands create immutable before/proposed state records and pass capability plus world-bound checks. Learner language cannot mutate scene coordinates directly; only an authenticated approval can apply a valid proposal.
- Media routing considers content type, quality tier, privacy, GPU availability, urgency and cost rather than sending every scene to one provider. Standard/Premium/Studio profiles use the requested 13 weighted VQS dimensions.
- Spatial tutoring is grounded in lesson scene objects: the selected object ID, spatial position, grade and approved knowledge accompany each response/event. Voice transcription fills a reviewable question; it does not execute actions directly.
- Plan images are private, bounded to 10 MB JPEG/PNG/WebP, checksummed and git-ignored. OpenCV/Tesseract output is normalized structured geometry with confidence and review status. Only accepted rooms can be scaled and materialized into the 3D scene.
- Every construction entity shares one persisted SceneObject transform contract and hierarchy. Natural-language changes create before/after proposals and require explicit approval before modifying geometry; unsupported instructions fail visibly rather than becoming guessed scene operations.
- Terminal voice commands use local faster-whisper, show the transcript and require confirmation before passing it as a single argument to Codex or Claude. Temporary microphone audio is deleted and audit logs retain only transcript hashes/lengths; no shell evaluation or permission bypass is allowed.
- Voice telephony uses Asterisk/PJSIP in an isolated loopback-only Docker runtime. SIP passwords remain generated mode-600 secrets, PostgreSQL stores only secret references, new inbound routes default disabled, and no carrier dialplan exists until registration is verified.
- The construction/education request is represented as a future provider-neutral industry pack (BIM/IFC scene graph, adaptive lesson, simulation, assessment, 3D/WebXR and renderer gateway), not mixed into the voice-call runtime.
- Voice AI uses versioned approved scripts and requires E.164, explicit consent basis and a current DNC check before an outbound record can be scheduled. Local WAV generation is not treated as a phone call; an absent provider produces a persistent blocked call/event.
- AI Content Factory is provider-neutral: Higgsfield, Kling, Veo, Sora, Seedance and Wan sit behind editable provider records, while 15 content types and 20 production stages can be manually assigned and updated. SEO and GEO metadata, variants, performance metrics and NPS remain project-linked evidence rather than decorative counters.
- The standalone Market Research Portal owns a separate digital-marketing evidence ledger for workspaces, provider readiness, assets, jobs, interactions, form attribution and audit events. Local espeak-ng + FFmpeg creates review-required narrated MP4 assets; external providers never report success without credentials and provider IDs.
- The new Marketing Operations Center uses real tenant-scoped aggregates and refreshes every 30 seconds; global-only chat/NPS metrics and missing integrations are explicitly labeled instead of manufacturing per-customer results.
- Marketing maturity is evidence-based across 21 capabilities: missing, installed, configured, data-flowing, and verified outcomes are distinct states. A healthy tool alone never counts as a successful campaign.
- Activepieces Community Edition is the open-source orchestration runtime. Its pinned container is loopback-only, telemetry-disabled, code-sandboxed and backed by isolated PostgreSQL/Redis with generated secrets.
- Mautic 6.0.6 is the campaign-management system of record; it runs as isolated web, MySQL, cron and worker services on loopback port 18090 rather than the repository's previous incomplete single-container stub.
- YouTube automation accepts only Postiz-ingested MP4 media with explicit title and visibility metadata; text-only variants and arbitrary URLs are never treated as successful video uploads.
- Public acquisition collection uses Crawlee only on same-origin public company pages with robots enforcement, serial rate limiting and bounded runs; LinkedIn/private social scraping and automatic outreach are explicitly excluded.
- Facebook and LinkedIn now share one Postiz auto-publisher so each platform variant is tracked independently and a multi-platform master draft is not marked published prematurely.
- The 28-channel roadmap distinguishes 19 supported publishing paths from 9 manual/assisted paths; limited APIs never become a pretext for browser-submitted marketing or bypassing platform rules.
- First-wave direct adapters resolve credentials only at runtime and fail closed when Telegram bot/channel, Discord webhook, Bluesky app-password, or Mastodon instance/token fields are absent.
- Facebook automation runs every five minutes but can claim only human-approved, due Facebook Page variants tied to a real connected Postiz account; missing credentials/account/approval is a safe no-op, never a reason to weaken controls.
- Public Meta OAuth reachability uses a restricted reverse proxy that exposes only the callback, required policy pages, and Meta setup screen; unrelated application routes return 404.
- Skyvern runs as a replaceable vendor runtime on loopback-only ports 18000/18080, uses host Ollama, and remains subordinate to the PostgreSQL provisioning state machine and human-action security gateway.
- Social provisioning extends the existing Next.js/PostgreSQL/Postiz portal rather than introducing a parallel FastAPI service; browser execution remains an isolated future adapter behind the database-backed state machine.
- CAPTCHA, OTP, 2FA, OAuth consent, identity/business verification, and terms acceptance are human tasks. No challenge response or secret is stored in PostgreSQL.
- Playwright/Chrome CDP and axe are the deterministic test authority; Stagehand/CUA is a bounded, optional local-Ollama enhancement.
- The quality self-healer may restart known services and queue repair review, but may not silently rewrite or publish code.
- The assistant now uses the existing `/api/ai/health` probe and the chat endpoint will return a clear 503 when Ollama is unavailable.
- Plain `oll "request"` now persists a request, creates a multi-job plan, runs specialist workers, monitors and retries, verifies results, synthesizes a grounded response, and prints it in the terminal. `oll chat` remains the explicit direct-chat path.
- Terminal execution and the minute cron worker share `/tmp/oll_worker.lock` to prevent concurrent GPU model thrashing.
- Periodic warm-up cron jobs were removed because they evicted active role models; role models load on demand.
- Social publishing infrastructure runs on custom loopback ports (Postiz 15080/15081 and OpenBao 18200), with a minute credential-sync timer and secrets excluded from source control.
- Social MCP operations require an authenticated administrator; protected publish/schedule/retry calls require a matching, unexpired, one-time database approval rather than accepting an arbitrary client-provided identifier.
- Operational social screens must not present generated examples as real accounts, followers, approvals, or publications; remaining generated tenant matrices carry a prominent SYNTHETIC DEMO DATA label.
